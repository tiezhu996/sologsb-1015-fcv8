# 古诗格律校勘台

面向诗词编辑与校勘人员的浏览器工作台。可逐字标注平仄、韵组和停顿，建立对仗关系，记录每条判断依据，并对多个异文版本进行并排定位。

## 状态所有权：校勘稿仓 / 历史底稿仓

应用把「当前校勘稿」与「历史底稿」拆成两个互不同源的本地仓：

| 仓 | localStorage key | 所有权 |
| --- | --- | --- |
| 当前校勘稿 | `sologsb-1015-draft-v2` | 唯一可编辑；逐字标注、改字、版本另存都只写入这里 |
| 历史底稿 | `sologsb-1015-archive-v1` | 只收**冻结归档包**：包内容不可改，只能追加、导入或整包撤回 |
| 导入检查点 | `sologsb-1015-import-journal-v1` | 导入/撤回事务的 journal，成功后自动清除 |

- 标注挂在**行身份**（去标点规范化句文，重复句按出现次序加 `#2` 消歧）而不是行号/字符位置上；句首插字、异文换字、整句换序时，标注按行内 LCS 对齐**随行随字迁移**，不再因改字而串位或误改底稿。
- 导入归档包时按**来源（版本名/出处）+ 上下文（同文次序、字形相似度、行序）**确定行身份；包内各版本分别匹配稿方版本。
- **不同字段自动合并**（稿方空、包方有值即收入）；**同一字段双方都有值且不一致**时生成冲突，保留稿方值并挂起到「历史底稿 → 待裁决冲突」，由人选择留校勘稿、取归档包或填自定义值（支持批量）。
- 找不到对应行/对应字的标注进入**未安置标注**清单，可人工安置到选中字或放弃，绝不静默丢弃。

### 写入失败、检查点与整包撤回

- 导入流程：先写 journal（内含**导入前整稿备份**）→ 写校勘稿仓 → 写归档仓与回执 → 全部成功后清 journal。
- 任一环节写入失败：两仓保持「不留半套历史」的一致语义，界面横幅提供**从检查点续做**（自动重试）与**撤回整包**（恢复导入前整稿）。
- 已完成的归档包也可在底稿卡片上**撤回整包**：按回执备份恢复校勘稿，并从底稿仓移除该包与回执。
- 首次打开发现旧版单仓数据（`sologsb-1015-poetry-workspace-v1`）时，自动迁移到两仓：标注键重排为行身份，迁移前内容冻结为一个历史底稿包；**旧 key 原样保留不删除**。

## 功能

- 录入诗句并按五言、七言格律模板逐字对照。
- 平仄、停顿、韵组、判断依据和批注可逐字维护。
- 自动提示出律位置、一三五位置可接受变体、待标字和重复用韵。
- 建立句间对仗关系（随行迁移），记录关系说明。
- 多版本独立校勘，字符级并排比较与上下处差异定位。
- 历史底稿归档/导入（.json 归档包）、字段冲突人工裁决、检查点续做与整包撤回。
- 文档级撤销/重做、键盘巡校和浏览器本地持久化。
- 导出包含字音标注、检查记录和版本来源的 Markdown 校对稿。
- 针对平板和桌面优化布局，支持长时编辑。

## 技术栈

- Angular 19（standalone components）
- TypeScript
- NG-ZORRO
- RxJS 与 Angular Signals
- Less
- 原生 `localStorage`（两仓 + 检查点，写入带重试）

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端提供的本地地址。

## 验证

```bash
npm run verify   # 无浏览器：行身份/LCS 迁移、字段合并冲突、检查点续做与整包撤回
npm test         # karma 组件套件（需 Chrome）
npm run build
```

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `↑ / ↓ / ← / →` | 在字格中移动 |
| `1 / 2 / 3` | 标为平 / 仄 / 中 |
| `R` | 循环切换韵组 |
| `Space` | 切换停顿标记 |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |
| `Ctrl/Cmd + S` | 本地保存提示 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t classical-poetry-meter-editor .
docker run --rm -p 10015:80 classical-poetry-meter-editor
```

宿主端口 `10015` 仅用于本地运行示例，实际端口由根编排文件统一管理。
